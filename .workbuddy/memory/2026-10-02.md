# 2026-10-02 — Expo Monorepo audit & fix pass

## Summary
Audited the Expo Management System monorepo (backend NestJS + frontend/public Vite-React + frontend/admin Vite-React). Found and fixed critical build/UI bugs; identified residual structural gaps.

## Critical bugs fixed (P0)
1. **Missing `postcss.config.js`** in both `frontend/public/` and `frontend/admin/`. Without it Vite never ran the Tailwind PostCSS plugin and the production CSS bundle was only **783 bytes** (just CSS variables) instead of the expected ~30 KB of utilities. As a result the entire UI rendered unstyled in production. Added `postcss.config.js` (CommonJS, with `tailwindcss` + `autoprefixer`) to both frontends. Bundle sizes jumped to **23 KB** (public) and **19 KB** (admin). Dev server now serves ~30 KB CSS for both.

## Cleanup (P1)
2. Removed duplicate `frontend/public/src/components/ui/ui/` folder — was a dead nested duplicate of `frontend/public/src/components/ui/` (badge/button/card/dialog/input/progress/separator/tabs/textarea). Never imported.
3. Replaced legacy `App.css` and `Sidebar.css` content in both frontends with one-line no-op comments. They were orphan files (no imports) with conflicting rules (`.sidebar ul li a` while Sidebar renders `<aside><nav><NavLink>` with no `<ul>`, body font-family overriding Tailwind, etc.).
4. Hardened `backend/nest/src/auth/auth.service.ts` — `validateUser` no longer accepts hardcoded `admin/admin` by default. Now requires `AUTH_ALLOW_DEV_LOGIN=true` AND non-production `NODE_ENV`, otherwise throws `UnauthorizedException`.
5. Strengthened `Contact.tsx` email validation: `includes('@')` → basic regex `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`.

### Pattern for future dark-mode work
1. Use semantic tokens (`bg-background`, `text-foreground`, `bg-card`, `border-border`, `text-muted-foreground`) wherever possible — these auto-flip via the CSS vars in `.dark`.
2. For raw color overrides, follow the convention: `bg-white dark:bg-slate-900`, `text-slate-900 dark:text-slate-100`, `bg-slate-50 dark:bg-slate-900/50`, `border-slate-200 dark:border-slate-800`, `hover:bg-slate-100 dark:hover:bg-slate-800`.
3. Don't sed-pass the same component twice — the second pass will match its own outputs and create stacked duplicates (`text-slate-500 dark:text-slate-400 dark:text-slate-500`).
4. Dark-gradient hero cards (e.g. on Home, Account, Login) should keep their dark colors in both modes — sed should skip them or use targeted edits.
